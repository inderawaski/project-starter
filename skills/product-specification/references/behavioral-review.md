# Concise behavioral review

Present an understandable **product behavior summary**, not a technical PRD.

Suggested format:
1. **Goal** (1–2 sentences)
2. **In scope / out of scope**
3. **User flow** (short numbered sequence)
4. **Important alternatives** (only material failure/partial flows)
5. **Key decisions** (not a transcript)
6. **Open assumptions** (only material ones)

Target 1–3 minutes to read for an ordinary feature. No exhaustive edge-case inventory, full acceptance criteria, or implementation task breakdown.

Request explicit approval. If corrected, update and re-present the affected understanding before authoring detailed tickets.
