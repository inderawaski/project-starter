# Linear authoring

Linear is the preferred storage when connected and authorized, not a hard dependency of this skill.

1. Confirm target team/project and whether to create a single issue or parent/children.
2. Search for existing relevant issues before creating duplicates.
3. Put the shared behavioral contract and scope in the parent or single issue.
4. Split children by independently implementable outcomes, not arbitrary layers.
5. Each issue needs a clear title, behavior, boundaries, and testable acceptance criteria.
6. Preserve links, dependencies, and decisions.
7. Create issues only **after explicit approval** of the concise behavioral review.
8. Report created issue identifiers and any failures accurately.

If Linear is unavailable, produce a structured Markdown draft. Do not claim it was saved remotely.
